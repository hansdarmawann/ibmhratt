Known risks and owner decisions:

1. **Dev/CI inclusion:** FLAML is in `requirements-dev.txt` so CI exercises the tests (measured cost above). Alternative: remove that line, and the FLAML tests skip in CI and the module's CI coverage drops (it might then reduce the pytest-only total).
2. **`flaml.tune` CFO instead of `flaml.AutoML`:** chosen to keep per-fold preprocessing, an identical search space, and no LightGBM/XGBoost. `flaml[blendsearch]` conflicts with Optuna 5. A `flaml.AutoML` benchmark would need a separate decision about its internal preprocessing and learners.
3. **Equal trial budgets** compare algorithms per evaluation, not FLAML's time-budgeted operating point (documented).
4. The FLAML version affects proposals; the `<3` range plus the lock pin limit drift.
5. Remote CI not run; the symlink test is skipped on this Windows host (pre-existing).
