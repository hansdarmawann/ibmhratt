### Ready-to-paste PR description

## Objective

Selection helpers previously received a partition object containing holdout labels, and the README described the holdout as scored once despite multiple candidate and diagnostic evaluations. Restrict selection inputs to training features and labels, enforce that data flow with behavioral regressions, and describe the actual evaluation procedure.

## Scope and files changed

- Narrow three selection/diagnostic helper signatures in `src/attrition/models/train.py`.
- Add six synthetic regression cases in `tests/test_evaluation_boundaries.py`.
- Correct `README.md`, document evaluation stages in `docs/methodology.md`, and record verified progress in `docs/pr-progress/PR-02.md`.

## Design and compatibility

- Existing behavior preserved: model settings, seeds, selection/threshold rules, public CLI and inference contract, artifact schema, and generated results.
- New interfaces/configuration: internal helpers take explicit training features and labels; no new dependency or public configuration.
- ML/data-boundary impact: test early holdout access, fold fitting, diagnostic ablation exclusion, exact outer-training inputs for tuning and threshold selection, and prohibition on reselection during holdout evaluation. Non-selected holdout comparisons remain post-selection descriptive diagnostics.
- The selected logistic model, threshold 0.20, baseline metrics, and train/holdout predictions are unchanged.
